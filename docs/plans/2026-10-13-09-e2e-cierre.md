# 09 · Pruebas de punta a punta, despliegue y cierre — Plan de implementación (rev. 4, por tareas)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Por tareas.** Este archivo fija archivos, interfaces, tests y criterios, pero no el código. Antes del incremento 3, el dueño de E2E-1 escribe el código detallado partiendo de `docs/plans/rev3/2026-10-13-09-e2e-cierre.md`. De ahí se reutilizan el `conftest.py` (httpx con la CA de mkcert y un cliente WebSocket con `shared.crypto`), los tests del gateway, el despliegue en el VPS y el guion de la demo. Cambios respecto de rev3:
> - Los participantes pasan a ser **cuentas** (registro + login).
> - El admin entra con TOTP calculado a partir del secreto de `create_admin`.
> - Se suman los flujos de RBAC y de moderación.

**Goal:** Demostrar contra el stack real lo que cruza servicios:
- cuentas, RBAC y revocación inmediata;
- chat cifrado entre dos clientes y moderación;
- imágenes publicadas o en cuarentena, con su alerta;
- las reglas del gateway: `/internal` cerrado, identidad no falsificable y TLS 1.3 obligatorio.

Además: calibrar `stego` con fotos reales, desplegar en un VPS con certificado válido y cerrar la trazabilidad R1–R16, el informe de pruebas, los documentos de cumplimiento y la demo final.

**Architecture:** `e2e/` es una suite pytest independiente que habla con `https://localhost` como lo haría un navegador:
- httpx con cookies (`__Host-session`, `__Host-device`), TLS verificado con la CA de mkcert y `Origin: https://localhost`;
- `websockets` (cliente síncrono) con el protocolo de `shared.crypto`.

El admin se crea una vez por corrida con `docker compose exec -T auth python -m auth_svc.create_admin e2e-admin --password-stdin`; el `TOTP_SECRET` que imprime se usa con `pyotp`.

**Tech Stack:** pytest, httpx, websockets, pyotp, `shared.crypto` / `shared.testing` · Docker Compose · certbot · Ubuntu 24.04.

**Spec:** `docs/specs/2026-10-12-chat-seguro-design.md` §12.4, §13, §16.2–§16.5, §18, §20.

## Global Constraints

Las del índice (`2026-10-13-00-indice.md`). En particular:
- La e2e corre con el stack levantado y nunca en CI (ClamAV es pesado).
- No se desactiva la verificación TLS en ninguna prueba.
- Cada test crea sus propios usuarios y salas (nombres con sufijo aleatorio), así que se puede repetir sin limpiar la BD.
- Commits en español, sin atribución.
