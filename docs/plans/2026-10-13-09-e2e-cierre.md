# 09 · Pruebas de punta a punta, despliegue y cierre — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Demostrar contra el stack real lo que cruza servicios:
- chat cifrado de punta a punta entre usuarios registrados;
- cuentas: sin cuenta no se entra a una sala, y la misma cuenta no inicia sesión desde un segundo dispositivo;
- reglas del gateway: `/internal` cerrado, identidad no falsificable (incluidas `X-User-*`), TLS 1.3 obligatorio;
- archivos publicados, en cuarentena o rechazados, con su alerta.

Además: desplegar en un VPS con certificado válido, calibrar el estegoanálisis con fotos y grabaciones reales y dejar la trazabilidad R1–R17 completa, el guion de la demo y el estado de `CLAUDE.md`.

**Architecture:** `e2e/` es una suite pytest independiente que habla con `https://localhost` exactamente como un navegador:
- httpx con cookies y TLS verificado con la CA de mkcert;
- `websockets` (cliente síncrono) con el protocolo de `shared.crypto`.

El admin se crea con el CLI de `auth` (`--password-stdin`). Las cuentas de usuario se registran por la API una sola vez por corrida (fixture `accounts`), porque el registro tiene tope por IP. Cada `Participant` es un navegador nuevo (su propio jar de cookies = un dispositivo) que inicia sesión, entra a la sala y, al terminar, sale y cierra la sesión para liberar la cuenta. El VPS usa el mismo Compose, con certificados de Let's Encrypt copiados por un hook de renovación.

**Tech Stack:** pytest, httpx, websockets, pyotp, shared.crypto/testing · Docker Compose · certbot · Ubuntu 24.04.

**Spec:** `docs/specs/2026-10-12-chat-seguro-design.md` §9.2, §12, §13, §16.2–§16.4, §18, §20.

> **Revisión 3 (2026-10-19).** El arnés crea cuentas de usuario y cada participante inicia sesión antes de entrar (`accounts`, `participant`, `new_browser`). Se suman pruebas de R17 (sin cuenta no se entra), R13 por cuenta, R6 en mensajes, MP3 y TXT, y R9 por contenido activo. La calibración incluye grabaciones WAV y la trazabilidad final cubre R1–R17. def ca_file() -> str:
```python
    if os.environ.get("E2E_CAFILE"):
        return os.environ["E2E_CAFILE"]
    caroot = subprocess.run(
        ["mkcert", "-CAROOT"], capture_output=True, text=True, check=True

def retry_429(send, attempts: int = 8):
    """El gateway limita login y join a 1 r/s (ráfaga 5): las pruebas esperan en vez de fallar."""
    response = send()
    for _ in range(attempts):
        if response.status_code != 429:
            return response
        time.sleep(1.2)
        response = send()
    return response

class Participant:
    """Una cuenta en un navegador: inicia sesión, entra a la sala y habla el lado cliente del protocolo."""

    def __init__(self, tls: ssl.SSLContext, room: dict, account: tuple[str, str]):
        self.tls, self.room = tls, room
        self.username, password = account
        self.http = new_browser(tls)
        self.login_response = retry_429(
            lambda: self.http.post(
                "/api/users/login", json={"username": self.username, "password": password}
            )
        )
        self.join_response = None
        if self.login_response.status_code == 200:
            self.join_response = retry_429(
                lambda: self.http.post(
                    "/api/rooms/join", json={"code": room["code"], "key": ROOM_KEY}
                )
            )
            if self.join_response.status_code == 200:
                self.session_id = self.join_response.json()["session_id"]
                self.room_id = self.join_response.json()["room"]["id"]
        self.sign_key = load_public_key(b64d(self.http.get("/chat-key.json").json()["pub"]))
        self.key, self.seq, self.recv_seq = None, 0, 0

    def close(self) -> None:
        """Sale de la sala y cierra la sesión: la cuenta queda libre para otro dispositivo."""
        self.http.post("/api/rooms/leave")
        self.http.post("/api/users/logout")
        self.http.close()

    def cookie_header(self) -> str:
        return "; ".join(f"{name}={value}" for name, value in self.http.cookies.items())

    def raw_connect(self, origin: str = BASE):
        return connect(
            WS_URL, ssl=self.tls, origin=origin, additional_headers={"Cookie": self.cookie_header()}
        )

    def connect(self):
        ws = self.raw_connect()
        private = ec.generate_private_key(CURVE)
        pub = b64e(public_bytes(private))
        ws.send(json.dumps({"t": "hello", "pub": pub}))
        reply = json.loads(ws.recv(timeout=10))
        transcript = hello_transcript(
            self.room_id, self.session_id, pub, reply["pub"], reply["salt"]
        )
        assert verify_p1363(self.sign_key, b64d(reply["sig"]), transcript), (
            "firma del hello inválida"
        )
        shared = private.exchange(ec.ECDH(), load_public_key(b64d(reply["pub"])))
        self.key = derive_session_key(shared, b64d(reply["salt"]), self.room_id, self.session_id)
        self.seq = self.recv_seq = 0
        return ws

    def send(self, ws, payload: dict) -> None:
        self.seq += 1
        ws.send(
            json.dumps(
                encrypt_frame(self.key, self.room_id, self.session_id, self.seq, "c2s", payload)
            )
        )

    def recv_until(self, ws, kind: str, **match) -> dict:
        while True:
            seq, payload = decrypt_frame(
                self.key, self.room_id, self.session_id, "s2c", json.loads(ws.recv(timeout=10))
            )
            assert seq > self.recv_seq
            self.recv_seq = seq
            if payload.get("t") == kind and all(payload.get(k) == v for k, v in match.items()):
                return payload


@pytest.fixture
def participant(tls, room, accounts):
    """Fábrica: participant("ana") inicia sesión con esa cuenta en un navegador nuevo y entra a `room`."""
    created: list[Participant] = []

    def make(name: str) -> Participant:
        created.append(Participant(tls, room, accounts[name]))
        return created[-1]

    yield make
    for each in reversed(created):
        each.close()
```

```python
def test_r12_imagen_limpia_se_publica_y_solo_la_baja_su_destinatario(participant):
    ana, beto = participant("ana"), participant("beto")
    # Todo dentro del `with`: cerrar el WS termina la sesión y la descarga exige sesión viva.

        event_for_beto = beto.recv_until(wb, "file")
```

- ≥ 30 imágenes propias (fotos de celular y capturas de pantalla, en PNG o JPEG);
- ≥ 20 grabaciones propias en WAV PCM de 16 bits (voz y música). Una nota de voz del celular se convierte con `ffmpeg -i nota.m4a -c:a pcm_s16le nota.wav`.

Ejecuta:
```bash
python services/media/tools/stego_lab.py calibrate services/media/tools/calibracion
```
Crea `docs/calibracion-estego.md` con:
- las tablas impresas (variante, detectadas, no concluyentes, medianas) de imágenes (chi² y RS) y de audio (SPA);
- la FPR (falsos positivos en "limpia") y la TPR en "seq 10%" y "random 10%" de cada detector;
- en audio, la fracción de grabaciones no concluyentes (`spa_rate = null`): esas quedan cubiertas solo por la sanitización, y es una limitación a declarar en el informe;
- los umbrales elegidos.

Si la FPR supera el 5 %, sube `STEGO_CHI2_P` (por ejemplo, a 0.99), `STEGO_RS_RATE` o `STEGO_WAV_RATE` en el `environment` de `media` en `deploy/docker-compose.yml` y vuelve a medir.
Expected: FPR ≤ 5 % en imágenes y en audio; TPR ≥ 90 % para LSB secuencial al 10 % en imágenes; en audio, la TPR y la fracción no concluyente documentadas.

`docs/despliegue-vps.md`:
````markdown
# Despliegue en un VPS (spec §18, S3)

Requisitos:
- Ubuntu 24.04 con ≥ 4 GB de RAM (ClamAV usa ~1.5–3 GB).
- Un dominio con registro A hacia la IP del VPS.
- Puertos 22, 80 y 443 abiertos.

## 1. Preparar el servidor
1. Instala Docker Engine y el plugin compose siguiendo https://docs.docker.com/engine/install/ubuntu/.
2. Firewall:
   ```bash
   sudo ufw allow OpenSSH && sudo ufw allow 80,443/tcp && sudo ufw enable
   ```
3. Dependencias para generar secretos y certificados:
   ```bash
   sudo apt install -y python3-cryptography certbot git
   ```

## 2. Código y secretos
```bash
git clone https://github.com/Steft91/SecureShop_CDM.git /srv/chat && cd /srv/chat
python3 deploy/gen_secrets.py
chmod 700 deploy/secrets
```

## 3. Certificado (Let's Encrypt)
```bash
export DOMAIN=chat.tu-dominio.com
mkdir -p deploy/certs
sudo certbot certonly --standalone -d "$DOMAIN" \
  --pre-hook "docker compose -f /srv/chat/deploy/docker-compose.yml stop gateway" \
  --post-hook "cp -L /etc/letsencrypt/live/$DOMAIN/fullchain.pem /etc/letsencrypt/live/$DOMAIN/privkey.pem /srv/chat/deploy/certs/ && docker compose -f /srv/chat/deploy/docker-compose.yml start gateway"
```
certbot guarda los hooks: cada renovación (cada ~60 días) detiene el gateway unos segundos, copia los certificados nuevos y lo vuelve a levantar. Prueba la renovación con `sudo certbot renew --dry-run`.

## 4. Configuración no secreta
```bash
echo "ALLOWED_ORIGINS=https://$DOMAIN" > deploy/.env
```
En ARM (por ejemplo, Oracle Cloud Free), ClamAV necesita la imagen multiarquitectura:
```bash
echo "CLAMAV_IMAGE=clamav/clamav-debian:1.4" >> deploy/.env
```
(Comprueba la arquitectura con `docker manifest inspect clamav/clamav:1.4 | grep arm64`.)

## 5. Levantar y crear el admin
```bash
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml exec auth python -m auth_svc.create_admin admin
```

## 6. Verificar
```bash
curl -sI http://$DOMAIN/ | head -1
curl -s --tlsv1.2 --tls-max 1.2 https://$DOMAIN/ -o /dev/null; echo "exit=$?"
curl -s https://$DOMAIN/internal/verify-admin
```
Expected: `301`, `exit` distinto de 0 y `{"error":"no encontrado"}`. Opcional: https://www.ssllabs.com/ssltest/ debería dar A o A+.

## Actualizar
```bash
git pull && docker compose -f deploy/docker-compose.yml up -d --build
```
Para redesplegar un solo servicio: `... up -d --build <servicio>`.
````

````markdown
# Guion de la demo (≈ 14 min)

1. **Arquitectura (1 min):** diagrama de la spec §4.1: gateway + 5 servicios + 5 BD + redes segmentadas.
2. **Borde (1 min):** `curl -I http://...` → 301; `curl --tlsv1.2 --tls-max 1.2` → falla; `/internal/verify-admin` → 404.
3. **Admin con TOTP (1 min):** login, código de la app, panel. Mostrar en *Auditoría* el `admin.login.ok`.
4. **Sala (1 min):** crear una sala con clave débil (rechazada) y luego con una válida. Mostrar en la BD que la clave está en Argon2id:
   `docker compose exec db psql -U postgres -d rooms -c "SELECT code, left(key_hash, 30) FROM rooms"`.
5. **Cuentas (1 min):** crear una cuenta con contraseña débil (rechazada) y luego con una válida. Mostrar en la BD que la contraseña está en Argon2id: `docker compose exec db psql -U postgres -d auth -c "SELECT username, left(password_hash, 30) FROM users"`. Iniciar sesión con la misma cuenta desde otro navegador → "la cuenta tiene una sesión activa en otro dispositivo".
6. **Chat cifrado (2 min):** dos navegadores (uno privado), cada uno con su cuenta. Mostrar las tramas en DevTools (`{"seq","n","c"}`) y en la BD (`SELECT payload FROM messages` en la BD chat → bytea ilegible). Enviar un mensaje con caracteres de ancho cero pegados: llega limpio y *Auditoría* muestra `msg.sanitized`.
7. **Estegoanálisis y archivos (2 min):** `stego_lab.py embed foto.jpg estego.png --rate 0.1`, `stego_lab.py append cancion.mp3 con_cola.mp3` y `stego_lab.py hide-text notas.txt oculto.txt --message "clave"`. Subir la foto, el MP3 y un PDF limpios (aparecen; el MP3 se reproduce y el PDF se descarga) y luego los tres archivos con datos ocultos (retenidos). Subir un `.docm` renombrado a `.docx` → rechazado. Mostrar *Cuarentena* con los motivos y *Auditoría* con `file.quarantined` y `file.rejected.active`. Liberar uno.
8. **Integridad de la auditoría (2 min):** *Verificar cadena* → íntegra. Como superusuario de Postgres (simulando un atacante con acceso a la BD):
   `docker compose exec db psql -U postgres -d audit -c "UPDATE audit_log SET actor='borrado' WHERE id=3"`.
   *Verificar cadena* → "alterada a partir del evento 3" y nueva alerta crítica `audit.chain.broken`.
9. **Confianza entre servicios (R16, 1 min):** desde el contenedor de `rooms`, llamar a audit sin token:
   `docker compose exec rooms python -c "import httpx; print(httpx.post('http://audit:8000/internal/events', json={}).status_code)"` → 401. El rechazo aparece en *Auditoría* como `svc.reject.token`.
10. **Cierre (1 min):** tabla de `docs/trazabilidad-riesgos.md` (17/17).
````
