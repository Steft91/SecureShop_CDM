# Salas de Chat Seguras — Plan de implementación (índice)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir la aplicación de salas de chat seguras del proyecto integrador con microservicios (gateway + auth, rooms, chat, media, audit) e implementar, con un test por riesgo, los 17 controles de seguridad (R1–R15 de la Tarea 2 + R16 y R17). Crear una cuenta (con correo verificado y alias) es obligatorio; todas las cuentas ven el canal general y se unen a las salas del admin con código y clave una sola vez. El chat acepta archivos de cualquier categoría (imagen, audio, video, documento y texto) con estegoanálisis, y toda versión sanitizada se reanaliza antes de publicarse. Además se cubren los requisitos no funcionales de la Actividad 3 (monitoreo, correlación, cobertura, complejidad, respaldos, carga y control de cambios).

**Architecture:** Nginx es el único punto de entrada: termina TLS 1.3, autentica con `auth_request` (admin, cuenta de usuario o sesión de sala) y propaga la identidad en cabeceras. Detrás hay cinco servicios FastAPI, cada uno con su propia BD dentro de un único PostgreSQL. Los servicios se comunican por REST interno con un token por servicio (allowlist por hash). El chat cifra cada conexión con ECDH P-256 + HKDF + AES-256-GCM, con un *hello* firmado con ECDSA. `media` acepta los 9 formatos de la lista blanca (PNG, JPEG, GIF, MP3, WAV, MP4, PDF, DOCX y TXT): los detecta por firma, los valida, los escanea con ClamAV, los analiza (chi²/RS en PNG, SPA en WAV y estructura en todos) y aplica rechazo, cuarentena o sanitización con reanálisis estructural de la salida. Cada petición lleva un `X-Request-ID` que aparece en los registros JSON de todos los servicios y en la auditoría; cada servicio expone métricas al panel y avisa si su CPU o memoria pasan el 80 % durante 5 minutos.

**Tech Stack:** Python 3.13, FastAPI, SQLAlchemy 2 async + asyncpg, Alembic, argon2-cffi, cryptography, pyotp, Pillow, numpy, scipy, pikepdf, lxml, mutagen, httpx · ffmpeg · PostgreSQL 17 · Nginx 1.27 · ClamAV 1.4 · React 19 + Vite + TypeScript · pytest, vitest · Docker Compose · GitHub Actions.

## Global Constraints

Valen para **todas** las tareas de **todos** los archivos del plan:

- **Versiones:** Python 3.13 (imagen `python:3.13-slim`), PostgreSQL 17, Nginx 1.27, ClamAV 1.4, Node 24 LTS, React 19, TypeScript ≥ 5.7 en modo `strict`.
- **Paquetes:** `services/shared` es la distribución `chat-shared` (se importa como `shared`); `services/<svc>` es la distribución `<svc>-svc` (se importa como `<svc>_svc`). **Ningún `pyproject.toml` declara `chat-shared` como dependencia**: se instala explícitamente, para evitar *dependency confusion* con un paquete homónimo en PyPI.
- **SQL:** SQLAlchemy `text()` con parámetros nombrados (`:param`). Nunca se interpolan datos en el texto SQL. Si un fragmento SQL constante se elige en código, se marca con `# noqa: S608` y un comentario.
- **Token de servicio:** toda ruta HTTP o WebSocket de un servicio exige `X-Service-Token` válido (middleware de `shared.web`), salvo `GET /health`.
  - Rutas públicas: `Depends(require_gateway | require_admin | require_user | require_session)`.
  - Rutas `/internal/*`: `Depends(allow("<llamador>", ...))`.
- **Errores al cliente:** siempre JSON `{"error": "<mensaje genérico en español>"}`. El detalle va solo a auditoría.
- **Cookies:** `__Host-admin`, `__Host-user`, `__Host-room` y `__Host-device`, con `Secure`, `HttpOnly`, `SameSite=Strict` y `Path=/` (`shared.web.set_cookie`).
- **Cuentas:** admins y usuarios nunca se mezclan (tablas, cookies y verificaciones distintas). La cuenta de usuario se identifica por su correo verificado; el alias visible se elige una vez en el primer ingreso. Una sola sesión activa por cuenta y una sola sesión de sala por usuario, ambas atadas a la cookie de dispositivo.
- **Observabilidad:** registros solo a través de `logging` (en Docker salen como JSON con `request_id`); ningún registro incluye contraseñas, códigos, tokens, cuerpos de mensajes ni la query de una URL firmada.
- **Calidad:** ninguna función con complejidad ciclomática mayor que 10 y cobertura de líneas ≥ 80 % por servicio (la CI lo exige desde FND-10).
- **Secretos:** solo desde `/run/secrets` (`shared.secrets`). Nunca en el código, en variables de entorno ni en `.env` versionado.
- **Transporte:** solo TLS 1.3 hacia el cliente. Nunca `ws://` (lo bloquea el hook `.claude/hooks/guard.py`).
- **Límites:** mensaje ≤ 2000 caracteres (sin controles salvo `\n`/`\t`, contados después de quitar los caracteres invisibles); trama WS ≤ 16384; subida ≤ 25 MB, con tope por categoría (imagen 5 MB, audio 10 MB, video 25 MB, documento 10 MB y texto 1 MB); imagen ≤ 20 MP; GIF ≤ 300 cuadros; Argon2id `m=64 MiB, t=3, p=4` con ≤ 4 cálculos concurrentes por proceso.
- **Archivos:** solo los 9 formatos de la lista blanca (spec §12.1), detectados por firma. El contenido activo (macros, JavaScript, adjuntos, OLE) se rechaza; todo lo publicado pasó por la sanitización y por el reanálisis estructural de la versión sanitizada, y se descarga como adjunto. ffmpeg y ffprobe solo se llaman desde `media_svc.ffmpeg`.
- **Idioma:** identificadores en inglés; comentarios, docstrings, mensajes de error y UI en español.
- **Pruebas:**
  - PostgreSQL real (`deploy/docker-compose.test.yml`, `127.0.0.1:5433`).
  - Servicios vecinos simulados con `shared.testing.Recorder`.
  - Cada riesgo tiene al menos un `test_rNN_*`.
- **Trazabilidad:** toda tarea que implementa un control actualiza su fila en `docs/trazabilidad-riesgos.md`.
- **Commits:** Conventional Commits en español, **sin líneas de atribución**, en la rama `feat/arquitectura-chat-seguro` (o ramas hijas por persona).

## Review Focus

Diez casos que el spec implica, pero que ningún criterio de aceptación nombra explícitamente. Cada uno tiene un test en la tarea dueña:

1. **Mensajes largos multibyte.** 2000 emojis o letras con tilde no deben cerrar la conexión (la trama queda en ~10.8 KB < 16 KB); con 2001 caracteres → 4400. → **CHAT-3**, `test_mensaje_largo_multibyte_no_cierra`.
2. **Código de sala con mayúsculas o espacios.** `" Sala-Uno "` y `sala-uno` son la misma sala; crear luego `SALA-UNO` → 409. → **ROOM-2**, `test_codigo_de_sala_normalizado`.
3. **Imágenes que no son RGB** (RGBA, paleta, escala de grises, 16 bits). Se analizan y sanitizan sin 500 y conservan la transparencia. → **MED-4**, `test_modos_de_imagen_no_rgb`.
4. **Volver a subir una imagen descargada del chat.** Los bytes ya sanitizados no van a cuarentena (se reconocen por `clean_sha256`). → **MED-4**, `test_reenvio_de_imagen_sanitizada_no_va_a_cuarentena`.
5. **Cerrar o recargar la pestaña (WS 1001).** Libera el cupo y la cuenta de inmediato; al volver a entrar desde el mismo dispositivo, la sesión nueva reemplaza a la anterior. → **CHAT-4**, `test_cierre_1001_termina_la_sesion`; **ROOM-4**, `test_end_libera_cupo_y_cuenta_una_sola_vez`; **ROOM-3**, `test_r13_recarga_en_el_mismo_dispositivo_reemplaza_la_sesion`.
6. **Archivos legítimos que parecen sospechosos.** Audio fuerte o ruidoso (SPA se abstiene en vez de marcarlo), un MP3 con etiquetas al final o con la última trama truncada, y un TXT con emojis compuestos (ZWJ) o BOM inicial no van a cuarentena. → **MED-7**, `test_spa_se_abstiene_con_audio_fuerte_o_ruidoso` y `test_etiquetas_finales_y_trama_truncada_son_legitimas`; **MED-10**, `test_txt_limpio_con_acentos_emojis_y_bom`.
7. **Formatos que se hacen pasar por otros.** Un ZIP cualquiera no es un DOCX, y un binario no entra como TXT (TXT se prueba al final porque no tiene firma). → **MED-9**, `test_otros_paquetes_zip_no_son_docx`; **MED-10**, `test_txt_va_al_final_y_no_atrapa_binarios`.
8. **Enrutamiento real del gateway.** `nginx -t` no detecta que una ruta llegue al servicio equivocado; la subpetición de `auth_request` comparte variables con la petición original. → **GW-2**, `gateway/tests/check_routes.py` (también en la CI).
9. **Mismo orden en vivo y en el historial.** Dos mensajes simultáneos no pueden difundirse en un orden distinto al de sus id. → **CHAT-3**, `test_rnf14_todos_reciben_todo_sin_duplicados_y_en_el_mismo_orden`.
10. **Registro sin enumeración ni secuestro de correos.** El registro responde lo mismo exista o no la cuenta, y una cuenta sin verificar se renueva con el próximo registro (solo el dueño del correo recibe el código). → **ATH-5**, `test_correo_con_cuenta_verificada_responde_igual_y_avisa` y `test_cuenta_sin_verificar_se_renueva_y_el_codigo_viejo_no_sirve`.

## Preparación del entorno local (una vez por integrante)

```bash
py -3.13 -m venv .venv
```
(En macOS/Linux: `python3.13 -m venv .venv`.) Actívalo (`.venv\Scripts\Activate.ps1` en PowerShell, `source .venv/bin/activate` en bash) e instala:
```bash
pip install -e "services/shared[dev]"
```
A medida que se creen los servicios, se instalan con `pip install -e services/<svc>`. Para las pruebas de MP3 y MP4 de `media` hace falta ffmpeg en el PATH (Windows: `winget install Gyan.FFmpeg`; macOS: `brew install ffmpeg`; sin él, esas pruebas se saltan). Para la BD de pruebas:
```bash
docker compose -f deploy/docker-compose.test.yml up -d
```
