# 04 · Gateway (Nginx) — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Punto de entrada único del sistema. Hace cuatro cosas:
- termina TLS 1.3 y redirige http → https;
- aplica cabeceras de seguridad y rate limit;
- sirve la SPA y `/chat-key.json`;
- enruta cada prefijo a su servicio, autenticando con `auth_request` y propagando la identidad sin dejar que el cliente la falsifique (R5, R7, R10, R16);
- genera el id de correlación de cada petición y deja un registro JSON por petición (RNF-19, rev. 4).

**Architecture:** Nginx 1.27 en una imagen multi-stage (Node compila la SPA y Nginx la sirve).
- Upstreams con variables y `resolver` de Docker: un servicio redeplegado (con IP nueva) sigue siendo alcanzable y un servicio que aún no existe da 503 JSON en vez de impedir el arranque.
- Cada `location` incluye exactamente un snippet de proxy:
  - `public.conf`: vacía toda la identidad;
  - `admin.conf`, `user.conf` o `session.conf`: identidad desde `auth_request` (admin, cuenta de usuario o sesión de sala).
- Todos los snippets inyectan `X-Service-Token` del gateway desde un Docker secret.

**Tech Stack:** Nginx 1.27-alpine, Node 24-alpine (build), mkcert, Docker Compose.

**Spec:** `docs/specs/2026-10-12-chat-seguro-design.md` §4.3–§4.5, §8.1, §9.2, §13, §16.2.

> **Revisión 3 (2026-10-19).** Cambian los snippets (8 cabeceras de identidad; `user.conf` nuevo; `session.conf` propaga `X-User-Id`) y `nginx.conf` (`/_auth/user`, rutas `/api/users/*`, `/api/rooms/join` exige cuenta, CSP con `media-src blob:`, subida de 25m). Si ya ejecutaste GW-1, reemplaza esos archivos y repite los pasos 4 y 5.
>
> **Revisión 4 (2026-10-20, spec rev. 4).** **Corrección en GW-1:** las ubicaciones `/_auth/*` usaban `set $upstream`, y como la subpetición de `auth_request` comparte variables con la petición original, las rutas autenticadas terminaban en el servicio que verificaba. Ahora usan `$verifier`; si ya ejecutaste GW-1, cambia esas tres ubicaciones. **GW-2, nueva:** rutas de verificación de correo, salas de la cuenta, métricas y estado; `X-Request-ID`; registros JSON; y una prueba de enrutamiento con servicios falsos que corre en la CI.

## Global Constraints

Las del índice (`2026-10-13-00-indice.md`). En particular:
- Solo TLS 1.3.
- Nunca `ws://`.
- Errores en JSON `{"error": "..."}`.
- Secretos solo desde `/run/secrets`.
- Commits en español, sin atribución.

## Review Focus

Ningún caso del índice cae aquí. A vigilar:
- una `location` que declara su propio `proxy_set_header` **deja de heredar** los del nivel `server`. Por eso cada `location` incluye un snippet completo y ninguna depende de herencia;
- la subpetición de `auth_request` **comparte variables** con la petición original: las ubicaciones `/_auth/*` usan `$verifier`, nunca `$upstream`;
- `X-Request-ID` se agrega una sola vez (en el `server`) y se oculta el que devuelve cada servicio (`proxy_hide_header`).

Las pruebas automáticas de estas reglas están en GW-2 (`gateway/tests/check_routes.py`, también en la CI) y en E2E-1 (`test_gateway_*`).

- [ ] **Step 2: `nginx.conf`**

`gateway/nginx.conf`:
```nginx
# Gateway del chat seguro (spec §13): único punto de entrada.
worker_processes auto;
events { worker_connections 1024; }

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;
    server_tokens off;
    sendfile      on;

    # DNS interno de Docker: los upstream se resuelven por request; un servicio redeplegado
    # (con IP nueva) sigue siendo alcanzable y uno ausente da 503 en vez de impedir el arranque.
    resolver 127.0.0.11 valid=10s ipv6=off;

    # Sin query string en los logs: las URL firmadas no quedan registradas.
    log_format main '$remote_addr "$request_method $uri" $status $body_bytes_sent $request_time';
    access_log /dev/stdout main;
    error_log  /dev/stderr warn;

    limit_req_zone  $binary_remote_addr zone=api:10m   rate=10r/s;
    limit_req_zone  $binary_remote_addr zone=login:10m rate=1r/s;
    limit_conn_zone $binary_remote_addr zone=perip:10m;
    limit_req_status  429;
    limit_conn_status 429;

    map $http_upgrade $connection_upgrade {
        default upgrade;
        ''      close;
    }

    server {
        listen 80;
        server_name _;
        return 301 https://$host$request_uri;   # ws:// nunca llega a un servicio (R7)
    }

    server {
        listen 443 ssl;
        http2 on;
        server_name _;

        ssl_certificate     /etc/nginx/certs/fullchain.pem;
        ssl_certificate_key /etc/nginx/certs/privkey.pem;
        ssl_protocols       TLSv1.3;
        ssl_session_tickets off;

        client_max_body_size 16k;
        client_body_timeout  10s;
        limit_conn perip 20;

        add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
        add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' blob:; media-src blob:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'" always;
        add_header X-Content-Type-Options "nosniff" always;
        add_header Referrer-Policy "no-referrer" always;
        add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;

        error_page 401 = @e401;
        error_page 403 = @e403;
        error_page 404 = @e404;
        error_page 413 = @e413;
        error_page 429 = @e429;
        error_page 500 502 503 504 = @e503;
        location @e401 { default_type application/json; return 401 '{"error":"no autenticado"}'; }
        location @e403 { default_type application/json; return 403 '{"error":"prohibido"}'; }
        location @e404 { default_type application/json; return 404 '{"error":"no encontrado"}'; }
        location @e413 { default_type application/json; return 413 '{"error":"archivo demasiado grande"}'; }
        location @e429 { default_type application/json; return 429 '{"error":"demasiadas solicitudes"}'; }
        location @e503 { default_type application/json; return 503 '{"error":"servicio no disponible"}'; }

        # --- autenticación delegada (subpeticiones internas) ---
        # La subpetición de auth_request COMPARTE las variables de la petición original: si aquí se
        # usara $upstream, se pisaría el destino de la ruta y la petición iría al servicio de la
        # verificación. Por eso estas ubicaciones usan $verifier.
        location = /_auth/admin {
            internal;
            set $verifier http://auth:8000;
            proxy_pass $verifier/internal/verify-admin;
            include /etc/nginx/snippets/subrequest.conf;
        }
        location = /_auth/user {
            internal;
            set $verifier http://auth:8000;
            proxy_pass $verifier/internal/verify-user;
            include /etc/nginx/snippets/subrequest.conf;
        }
        location = /_auth/session {
            internal;
            set $verifier http://rooms:8000;
            proxy_pass $verifier/internal/verify-session;
            include /etc/nginx/snippets/subrequest.conf;
        }

        # --- SPA y clave pública de firma del chat ---
        location / {
            root /usr/share/nginx/html;
            try_files $uri /index.html;
        }
        location = /chat-key.json {
            root /srv/public;
            default_type application/json;
        }

        # --- auth ---
        location = /api/auth/login {
            limit_req zone=login burst=5 nodelay;
            set $upstream http://auth:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/public.conf;
        }
        location = /api/auth/totp {
            limit_req zone=login burst=5 nodelay;
            set $upstream http://auth:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/public.conf;
        }
        location /api/auth/ {
            limit_req zone=api burst=20 nodelay;
            set $upstream http://auth:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/public.conf;
        }
        location = /api/users/register {
            limit_req zone=login burst=5 nodelay;
            set $upstream http://auth:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/public.conf;
        }
        location = /api/users/login {
            limit_req zone=login burst=5 nodelay;
            set $upstream http://auth:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/public.conf;
        }
        location /api/users/ {
            limit_req zone=api burst=20 nodelay;
            set $upstream http://auth:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/public.conf;
        }

        # --- rooms ---
        location = /api/device {
            limit_req zone=api burst=20 nodelay;
            set $upstream http://rooms:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/public.conf;
        }
        location = /api/rooms/join {
            limit_req zone=login burst=5 nodelay;
            set $upstream http://rooms:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/user.conf;   # sin cuenta no se entra a ninguna sala
        }
        location = /api/rooms/leave {
            limit_req zone=api burst=20 nodelay;
            set $upstream http://rooms:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/session.conf;
        }
        location /api/admin/rooms {
            limit_req zone=api burst=20 nodelay;
            set $upstream http://rooms:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/admin.conf;
        }

        # --- media ---
        location = /api/media/files {
            client_max_body_size 25m;   # el tope de cada categoría lo aplica media (spec §12.1)
            limit_req zone=api burst=20 nodelay;
            set $upstream http://media:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/session.conf;
        }
        location /api/media/ {
            limit_req zone=api burst=20 nodelay;
            set $upstream http://media:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/session.conf;
        }
        location /api/admin/quarantine {
            limit_req zone=api burst=20 nodelay;
            set $upstream http://media:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/admin.conf;
        }

        # --- audit ---
        location /api/admin/audit {
            limit_req zone=api burst=20 nodelay;
            set $upstream http://audit:8000;
            proxy_pass $upstream;
            include /etc/nginx/snippets/admin.conf;
        }

        # --- chat (WebSocket) ---
        location = /ws {
            set $upstream http://chat:8000;
            proxy_pass $upstream;
            proxy_http_version 1.1;
            proxy_set_header Upgrade    $http_upgrade;
            proxy_set_header Connection $connection_upgrade;
            proxy_read_timeout 75s;
            include /etc/nginx/snippets/session.conf;
        }

        # Nada más bajo /api ni /internal existe hacia afuera (R16).
        location /api/      { return 404; }
        location /internal/ { return 404; }
    }
}
```

> **Por qué la prueba de enrutamiento.** `nginx -t` solo valida la sintaxis. La primera corrida de esta prueba encontró que las subpeticiones de `auth_request` comparten variables con la petición original: como `/_auth/*` hacía `set $upstream …`, casi todas las rutas autenticadas iban al servicio que verificaba (por ejemplo, `/api/admin/rooms` terminaba en auth y `/ws` en rooms). GW-1 ya usa `$verifier` en esas ubicaciones; esta prueba impide que vuelva a pasar.

        self.send_header("Content-Type", "application/json")
        self.send_header("X-Request-ID", "del-servicio")

"""Enrutamiento del gateway contra servicios falsos (GW-2): cada ruta llega a su servicio, con la
identidad que puso el gateway (nunca la del cliente) y un único X-Request-ID generado por nginx."""

import sys

import httpx

BASE = sys.argv[1] if len(sys.argv) > 1 else "https://127.0.0.1:18443"
UUID = "123e4567-e89b-42d3-a456-426614174000"
SPOOFED = {
    "Origin": "https://localhost",
    "X-Request-ID": "del-cliente",
    "X-Admin-Id": "falso",
    "X-User-Id": "falso",
}
# (método, ruta, servicio, ruta que recibe el servicio o None si es la misma, cabecera de identidad)
ROUTES = [
    ("POST", "/api/auth/login", "auth", None, None),
    ("POST", "/api/users/register", "auth", None, None),
    ("POST", "/api/users/verify", "auth", None, None),
    ("POST", "/api/users/verify/resend", "auth", None, None),
    ("GET", "/api/users/me", "auth", None, None),
    ("GET", "/api/device", "rooms", None, None),
    ("GET", "/api/rooms", "rooms", None, "x-user-id"),
    ("POST", "/api/rooms/join", "rooms", None, "x-user-id"),
    ("POST", f"/api/rooms/{UUID}/enter", "rooms", None, "x-user-id"),
    ("DELETE", f"/api/rooms/{UUID}/membership", "rooms", None, "x-user-id"),
    ("POST", "/api/rooms/leave", "rooms", None, "x-session-id"),
    ("GET", "/api/admin/rooms", "rooms", None, "x-admin-id"),
    ("GET", "/api/admin/quarantine", "media", None, "x-admin-id"),
    ("GET", "/api/admin/audit", "audit", None, "x-admin-id"),
    ("POST", "/api/media/files", "media", None, "x-session-id"),
    ("GET", "/api/media/files/abc", "media", None, "x-session-id"),
    ("GET", "/ws", "chat", None, "x-session-id"),
    ("GET", "/api/status", "chat", "/health", None),
    *[
        ("GET", f"/api/admin/metrics/{s}", s, "/api/admin/metrics", "x-admin-id")
        for s in ("auth", "rooms", "chat", "media", "audit")
    ],
]
NOT_ROUTED = [
    "/internal/verify-user",
    "/api/otra",
    f"/api/rooms/{UUID}/otra",
    "/api/admin/metrics/db",
]


def check(
    client: httpx.Client, method: str, path: str, service: str, upstream, identity
) -> list[str]:
    r = client.request(method, path)
    if r.status_code != 200:
        return [f"{method} {path}: HTTP {r.status_code}"]
    body, problems = r.json(), []
    headers, ids = body["headers"], r.headers.get_list("x-request-id")
    if (body["svc"], body["path"]) != (service, upstream or path):
        problems.append(f"{method} {path}: llegó a {body['svc']} {body['path']}")
    if len(ids) != 1 or ids[0] == "del-cliente" or headers.get("x-request-id") != ids[0]:
        problems.append(f"{method} {path}: X-Request-ID {ids} / {headers.get('x-request-id')}")
    for name in ("x-admin-id", "x-user-id", "x-session-id"):
        value = headers.get(name)
        if (
            value == "falso"
            or (name == identity) != bool(value)
            and not (name == "x-user-id" and identity == "x-session-id")
        ):
            problems.append(f"{method} {path}: {name}={value!r}")
    return problems


def main() -> None:
    client = httpx.Client(base_url=BASE, verify=False, headers=SPOOFED)  # noqa: S501 — certificado de prueba
    problems = [p for route in ROUTES for p in check(client, *route)]
    problems += [f"{p}: debería ser 404" for p in NOT_ROUTED if client.get(p).status_code != 404]
    print("\n".join(problems) or f"{len(ROUTES) + len(NOT_ROUTED)} rutas correctas")
    sys.exit(1 if problems else 0)


if __name__ == "__main__":
    main()
